# 0003: The web host on bazzite

Status: verified (2026-10-18)

Goal: `tools/install_web_build.sh` builds every demo of a commit (HEAD or the argument) into `bin/web/builds/<commit>/` and switches `bin/web/current`, two builds kept as the play build install of Mine oh Belowed keeps them; an index page at the root lists the demos with the installed commit; a systemd user service serves `bin/web/current` over plain http on the LAN, so the phone and the laptop open `http://bazzite:<port>/`. `doc/build.md` names the port and the service.

Verify:
- `tools/install_web_build.sh` installs HEAD and the index page lists the hello demo with its commit.
- The phone and the laptop open the index and the hello page over the LAN (the user).

## Specification (main agent, 2026-10-18)

Facts measured on bazzite on 2026-10-18: the LAN address is 192.168.1.7, port 8080 is free, firewalld runs with the FedoraWorkstation zone which already opens 1025 to 65535 on TCP, so no firewall change is needed. `python3 -m http.server` (Python 3 on the host) serves `.wasm` as `application/wasm` and takes `--directory` and `--bind`. The user's session has no linger, so a user service runs while the user is logged in, which is the normal state of the couch machine.

- `tools/install_web_build.sh` (new, executable), the shape of Mine oh Belowed's `tools/install_play_build.sh` (`~/dev/mine-oh-belowed/tools/install_play_build.sh`: `set -euo pipefail`, `usage`, one optional commit argument defaulting to `HEAD`, `repository_root` from `BASH_SOURCE/..`, `mktemp -d` staging with a `trap` that removes it, `switch_current_build` by `ln -sfn` then `mv -Tf`, `remove_old_builds` keeping the two newest) without the launcher, the `--target` option and the `pgrep` check. `web_root="$repository_root/bin/web"`, `commit="$(git -C "$repository_root" rev-parse --short "$ref")"`, `build_name="$(date -u +%Y%m%dT%H%M%SZ)-$commit"`. The build: `git -C "$repository_root" archive "$ref" | tar -x -C "$staging"`, then in the staging directory, for every `src/demos/*/`, `BEDROCK_ARRAY_COMMIT="$commit" ./build.sh web "$demo"`; then `mkdir -p "$web_root/builds"` and `cp -r "$staging/build/web" "$web_root/builds/$build_name"`. The index: `$web_root/builds/$build_name/index.html` written by the script with a heredoc, a page titled `Bedrock Array demos` with inline CSS (dark background, light text, one link per line in a large font for a phone), one `<a href="<demo>/"><demo></a>` per demo, and a footer line `commit <commit>, built <UTC time>`. Then `switch_current_build`, `remove_old_builds` with 2, and a last line printing `installed <build_name>, http://192.168.1.7:8080/` with the address read from `hostname -I | awk '{print $1}'`.
- `tools/bedrock-array-web.service` (new): a systemd user unit. `[Unit]` with `Description=Bedrock Array demo pages`; `[Service]` with `ExecStart=/usr/bin/python3 -m http.server 8080 --bind 0.0.0.0 --directory %h/dev/bedrock-array/bin/web/current` and `Restart=on-failure`; `[Install]` with `WantedBy=default.target`. Not enabled by the implementer: the main agent enables it.
- `doc/build.md`: a section `## The web host` (the unit file and the three commands that enable it: `ln -sfn "$PWD/tools/bedrock-array-web.service" ~/.config/systemd/user/`, `systemctl --user daemon-reload`, `systemctl --user enable --now bedrock-array-web.service`; the port, the URL `http://192.168.1.7:8080/` and `http://bazzite:8080/` where the name resolves; that the firewall zone already opens the port; that `loginctl enable-linger` would keep it up without a login) and a section `## Installing the demos` (the install script, the archive build so the working tree is never served, `BEDROCK_ARRAY_COMMIT` for the stamp, the double buffering with two builds kept and the one rename that switches `current`, run after every commit on `main`).

Verify: `tools/install_web_build.sh` on HEAD prints the installed name and the URL, `bin/web/current/index.html` lists `hello` with the commit, and after the service is enabled `curl -s http://127.0.0.1:8080/` returns that index; the phone and the laptop open it over the LAN (the user).
