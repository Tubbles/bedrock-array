# 0073: The scene view out of the web page

Status: landed (2026-10-19, c59b6db)

Goal: the part of the web page that is not the browser (the library, the scene, the renderer, the meshes, the fly camera, the labels' projection) becomes a `Scene_View` without a build tag, so the native app runs the same scenes through it. The web page keeps the canvas, the events, the pointers, the keys, the gamepad and the label exports, and feeds the view an input per frame.

Verify:
- `./build.sh check` and `./build.sh test` pass (`src/engine` natively compiles the view); `./build.sh web light` and `web models` build and the pages behave as before.

## Specification

- `src/engine/scene_view.odin` (no build tag): `Scene_Input :: struct { walk: [3]f32, turn: [2]f32 }` (walk as a direction per axis, right, up and forward, each minus one to one, turn in radians, yaw then pitch, already scaled by the caller); `Scene_View :: struct { library, scene, renderer: Gl_Renderer, item_mesh_ids, item_half_extents, draw_list, fly: Fly }`; the constants `SCENE_VIEW_VERTICAL_FOV`, `SCENE_VIEW_DISTANCE_MAXIMUM`, `SCENE_VIEW_FLY_SPEED`, `SCENE_VIEW_STEP_LIMIT` moved from the page (the page's `SCENE_PAGE_` copies go); `scene_view_init(view, library_data, scene_data: []byte, textures, meshes: []runtime.Load_Directory_File, aspect: f32) -> (problem: string)`: the library, the scene, the fit at the aspect and the fly from it, the renderer init (`"the GL shaders did not compile"`), the mesh and texture uploads (the page's two upload procedures move here as `scene_view_upload_meshes` and `scene_view_upload_textures`); `scene_view_step(view, input: Scene_Input, delta_time: f32)`: the step limit, `fly_walk` by `input.walk` at the speed, `fly_turn` by `input.turn` with a radians per pixel of 1; `scene_view_draw(view, width, height: i32)`: the draw list from the scene and the fly camera as the page's step builds it today, then `gl_renderer_draw`; `scene_view_camera(view) -> Camera`; `scene_view_label_screen(view, index: int, canvas: [2]f32) -> (pixel: [2]f32, visible: bool)` through `world_to_screen`; `scene_view_destroy`.
- `src/engine/web_scene_page.odin`: `Scene_Page` holds a `view: Scene_View` in place of the library, scene, renderer, mesh ids, half extents, draw list and fly; `scene_page_init` resizes, listens and calls `scene_view_init` with `page.aspect`; `scene_page_step` composes the `Scene_Input` from the keys (walk), the primary pointer's turn accumulated since the last step (a new `page.turn_pending: [2]f32` the pointer move adds `movement * SCENE_PAGE_DRAG_RADIANS_PER_PIXEL` to and the step clears) and the gamepad (walk from the sticks and the d-pad, turn from the right stick times `SCENE_PAGE_STICK_TURN_RADIANS_PER_SECOND * delta_time`), calls `scene_view_step` then `scene_view_draw` with the canvas size; the label exports read `scene_view_label_screen` with the CSS pixel canvas. The page keeps `SCENE_PAGE_DRAG_RADIANS_PER_PIXEL`, `SCENE_PAGE_STICK_DEAD_ZONE`, `SCENE_PAGE_STICK_TURN_RADIANS_PER_SECOND`.
- `doc/render.md`: the scene files paragraph names `Scene_View` (`src/engine/scene_view.odin`) as what draws a scene from its data and an input, and `Scene_Page` as the browser's glue around it.
