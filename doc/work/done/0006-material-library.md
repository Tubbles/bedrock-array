## Specification (main agent, 2026-10-18)

Builds on 0004 (`Material_Id` in `render_draw_list.odin`, `doc/render.md`). Parsing follows Mine oh Belowed's strict pattern (`parse_blueprint` in its `src/command.odin`): `json.parse(data, .SJSON, true, context.temp_allocator)` to a value tree, then every key checked by hand, so an unknown key or a value out of range is a problem the caller reports. Ids are deterministic: `json.Object` is a map, so the names are sorted and the index in sorted order is the `Material_Id`.

- `data/materials/library.sjson` (new): six presets, one object each, with the keys `albedo` (three numbers, each 0 to 1), `roughness` (0 to 1), `metallic` (0 to 1) and `emissive` (three numbers, 0 or more, optional, default zero). A comment line above the file saying what the keys mean and that albedo is the paint or surface colour for a dielectric (`metallic = 0`) and the reflectance colour for a metal (`metallic = 1`). Values: `painted_steel` albedo `[0.20, 0.24, 0.30]`, roughness 0.55, metallic 0 (paint is a dielectric over the steel); `bare_alloy` albedo `[0.91, 0.92, 0.92]`, roughness 0.35, metallic 1 (aluminium's reflectance); `copper` albedo `[0.95, 0.64, 0.54]`, roughness 0.30, metallic 1; `glass` albedo `[0.90, 0.95, 1.00]`, roughness 0.05, metallic 0; `rubber` albedo `[0.05, 0.05, 0.05]`, roughness 0.90, metallic 0; `concrete` albedo `[0.55, 0.55, 0.52]`, roughness 0.95, metallic 0.
- `src/engine/material.odin` (new, `package engine`): `Material :: struct { name: string, albedo: [3]f32, roughness, metallic: f32, emissive: [3]f32 }`, `Material_Library :: struct { materials: []Material }` indexed by `Material_Id`. `parse_material_library :: proc(data: []byte, allocator := context.allocator) -> (library: Material_Library, problem: string)`: a problem is a short text naming the material and the key (`material copper: unknown key shine`, `material glass: roughness 1.5 is outside 0 to 1`, `material rubber: albedo missing`, `not SJSON: <error>`), empty when all is well; names are cloned into the allocator; a number is a `json.Float` or a `json.Integer`, read through one helper `material_number :: proc(value: json.Value) -> (f32, bool)`; a colour is a `json.Array` of three numbers read through `material_colour`. `material_library_destroy :: proc(library: ^Material_Library, allocator := context.allocator)` frees the names and the slice. `material_id_by_name :: proc(library: Material_Library, name: string) -> (Material_Id, bool)`, a linear search.
- `src/engine/material_test.odin` (new, first line `#+build !js` as every engine test file): `test_material_library_parses_the_shipped_file` (`#load("../../data/materials/library.sjson")`: six materials, `material_id_by_name` finds `copper` and its metallic is 1, the names come out sorted so `bare_alloy` is id 0), `test_material_library_rejects_an_unknown_key` (a small SJSON text with `shine = 1`: the problem contains `unknown key shine`), `test_material_library_rejects_a_roughness_out_of_range` (roughness 1.5: the problem names roughness), `test_material_library_rejects_a_missing_albedo`. Every library the tests build is destroyed with `defer`.
- `doc/render.md`: a section `## Materials` (the library file, the keys and their ranges, the alphabetical id rule and why, the dielectric and metal meaning of albedo in one sentence).

Verify: `./build.sh check` and `./build.sh test` pass with the four new tests.
