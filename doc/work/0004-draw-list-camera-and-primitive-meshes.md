# 0004: The draw list, the camera and the primitive meshes

Status: verified (2026-10-18)

Goal: the render files of the `engine` package, native and pure: `Draw_List` (a camera, a sun, draw items of mesh id, material id and transform), `Camera` with its view and projection matrices and an orbit constructor (target, yaw, pitch, distance), and the primitive meshes `box_mesh` and `cylinder_mesh` (positions, normals, indices). No WebGL here: the package is what the demos and later the modules fill, and what the WebGL side reads. The first step of D1, split from the renderer skeleton.

Verify:
- `./build.sh test` passes with tests on the matrices (a camera on the z axis looking at the origin maps the origin to the view's centre), the orbit (yaw and pitch give the expected position), and the meshes (vertex and index counts, unit normals, a box's normals axis aligned).

## Specification (main agent, 2026-10-18)

Layout decision carried by this item: `src/engine/` stays one package, `engine`, split into files by concern as Mine oh Belowed's game package is, because `odin test src/engine -all-packages` reaches imported packages only and web only code is kept out of native builds by a build tag on its files, not by a package. The render files are `render_camera.odin`, `render_draw_list.odin`, `render_mesh.odin` and `render_test.odin`, all `package engine`. Coordinates: metres, y up, right handed, OpenGL clip space (`core:math/linalg` with its `flip_z_axis` default), counter clockwise front faces seen from outside.

- `render_camera.odin`: `Camera :: struct { position, target, up: [3]f32, vertical_fov_radians, near, far: f32 }`. `Orbit :: struct { target: [3]f32, yaw, pitch, distance: f32 }`. `orbit_camera :: proc(orbit: Orbit, vertical_fov_radians, near, far: f32) -> Camera` with position = target + distance times `{cos(pitch) * sin(yaw), sin(pitch), cos(pitch) * cos(yaw)}` and up `{0, 1, 0}`. `view_matrix :: proc(camera: Camera) -> matrix[4, 4]f32` through `linalg.matrix4_look_at_f32(camera.position, camera.target, camera.up)`. `projection_matrix :: proc(camera: Camera, aspect: f32) -> matrix[4, 4]f32` through `linalg.matrix4_perspective_f32(camera.vertical_fov_radians, aspect, camera.near, camera.far)`.
- `render_draw_list.odin`: `Mesh_Id :: distinct u32`, `Material_Id :: distinct u32`, `Directional_Light :: struct { direction, colour: [3]f32, intensity: f32 }`, `Draw_Item :: struct { mesh: Mesh_Id, material: Material_Id, transform: matrix[4, 4]f32 }`, `Draw_List :: struct { camera: Camera, sun: Directional_Light, items: [dynamic]Draw_Item }`. `draw_list_add :: proc(list: ^Draw_List, mesh: Mesh_Id, material: Material_Id, transform: matrix[4, 4]f32)`, `draw_list_clear :: proc(list: ^Draw_List)` (keeps the capacity), `draw_list_destroy :: proc(list: ^Draw_List)`.
- `render_mesh.odin`: `Vertex :: struct { position, normal: [3]f32 }`, `Mesh_Data :: struct { vertices: []Vertex, indices: []u32 }`. `box_mesh :: proc(size: [3]f32, allocator := context.allocator) -> Mesh_Data`: centred at the origin, six faces of four vertices each carrying the face normal, 24 vertices and 36 indices. `cylinder_mesh :: proc(radius, height: f32, segments: int, allocator := context.allocator) -> Mesh_Data`: axis y, centred at the origin; the side has two rings of `segments + 1` vertices (the seam vertex repeated) with radial normals and `6 * segments` indices; each cap has one centre vertex and `segments` ring vertices with the cap's normal, fanned with wrap around, `3 * segments` indices; so `4 * (segments + 1)` vertices and `12 * segments` indices in all. `mesh_data_destroy :: proc(mesh: ^Mesh_Data, allocator := context.allocator)`.
- `render_test.odin`: a local `expect_near :: proc(t: ^testing.T, got, expected: f32, tolerance: f32 = 1e-5)` helper, then `test_view_matrix_puts_the_target_on_the_view_axis` (camera at `{0, 0, 5}` looking at the origin, up y: the origin maps to `{0, 0, -5, 1}`), `test_projection_maps_near_and_far_to_the_clip_range` (aspect 1, fov pi/2, near 0.1, far 100: a point at z = -0.1 divides to clip z -1, one at z = -100 to clip z 1), `test_orbit_camera_sits_behind_the_target_at_yaw_zero` (distance 5: position `{0, 0, 5}`, up `{0, 1, 0}`), `test_orbit_camera_rises_with_pitch` (pitch pi/4: y and z both `5 * sqrt(2) / 2`), `test_box_mesh_has_six_faces` (size `{2, 2, 2}`: 24 vertices, 36 indices, every position component is 1 or -1, every normal has one component of 1 or -1 and two of 0, each of the six directions occurs four times, every index is below 24), `test_cylinder_mesh_counts_and_normals` (radius 1, height 2, segments 8: 36 vertices, 96 indices, every normal has unit length, the side normals have y 0, every index is below 36), `test_draw_list_add_and_clear` (two adds give two items, clear gives none). Every mesh and list the tests allocate is destroyed with `defer`, since the test runner tracks memory.
