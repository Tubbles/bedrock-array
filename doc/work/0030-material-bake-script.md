# 0030: The material bake script

Status: verified (2026-10-18)

Goal: step 2 of `doc/workflows/materials.md`: `tools/materials/bake.py` turns a bake parameter file into the three tileable maps, and the first parameter file, worn painted steel, with its baked set committed through Git LFS. Refers to items 0028 and 0029.

Verify:
- `flatpak run org.blender.Blender -b --python "$PWD/tools/materials/bake.py" -- painted_steel` writes `data/materials/textures/painted_steel_albedo.png`, `_normal.png` and `_surface.png`, 512 square, and prints the seam check with every map's seams within 1.5 times the image's mean neighbour step.

## Specification (main agent, 2026-10-18)

Binding facts, verified 2026-10-18 in the design probe of 0028: the flatpak sees the host filesystem; Blender's bundled Python has numpy and OpenImageIO 3.1 and no PIL; `bpy.ops.wm.read_factory_settings(use_empty=True)`, Cycles on `CPU` with 1 sample, a plane of size 2 with a material whose active node is an image texture node, `bpy.ops.object.bake(type='EMIT', margin=0)` into that image, `image.pixels` read into numpy as `(size, size, 4)` bottom row first; `ShaderNodeTexNoise` with `noise_dimensions = '4D'` takes `Vector` and `W`; the torus mapping of the UV, `Vector = 1.2 * (cos 2πu, sin 2πu, cos 2πv)` and `W = 1.2 * sin 2πv`, makes every channel periodic (seam difference 0.0044 against 0.0049 between neighbours at 1024).

- `data/materials/bake/painted_steel.sjson`: a one line comment, then `seed = 7`, `tile_metres = 2`, `paint = { mottle_amount = 0.08 mottle_scale = 5 roughness = 0.55 roughness_variation = 0.12 orange_peel_height = 0.0015 orange_peel_scale = 60 }`, `steel = { roughness = 0.35 roughness_variation = 0.1 scale = 8 }`, `wear_field = { voronoi_scale = 4 noise_scale = 7 blend = 0.5 }`, one member per line.
- `tools/materials/bake.py`, run as `flatpak run org.blender.Blender -b --python "$PWD/tools/materials/bake.py" -- <name> [size]` from the repository root (the flatpak starts in its own directory, so the path is absolute), size 512 by default. It puts its own directory on `sys.path` and reads `data/materials/bake/<name>.sjson` with `sjson.parse` (item 0029), the repository root being two directories above the script. It resets Blender as above and builds one node tree whose channels all read the torus mapped coordinate, with the seed added to `W` so another seed is another tile: `mottle`, 4D noise at `paint.mottle_scale`, detail 4; `orange_peel`, 4D noise at `paint.orange_peel_scale`, detail 2; `steel_noise`, 4D noise at `steel.scale`, detail 3; `wear_field`, `mix(1 - voronoi F1 distance at wear_field.voronoi_scale (4D, `ShaderNodeTexVoronoi`), noise at wear_field.noise_scale (4D), wear_field.blend)`, the inversion so the field is high at the cell centres and the chips come out as flakes rather than a ridge network (seen on the first bake). Each channel is baked on its own by linking it to the emission colour and baking into a fresh float image, read back into numpy, in a procedure `bake_channel(tree, socket, size) -> array`.
- Assembly in numpy, in Blender's bottom row first order: `albedo = 1 - paint.mottle_amount * mottle` as grey; `height = paint.orange_peel_height * (orange_peel - 0.5)`, slopes by central differences with `numpy.roll` (so the normal tiles) over `texel_metres = tile_metres / size`, `normal = normalize(-slope_u, -slope_v, 1)` encoded `normal * 0.5 + 0.5`, +Y up, which the bottom first order gives; `surface` with R `paint.roughness + paint.roughness_variation * (mottle - 0.5) * 2`, G `steel.roughness + steel.roughness_variation * (steel_noise - 0.5) * 2`, B the wear field stretched to span 0 to 1, all clipped to 0 to 1.
- Writing through OpenImageIO (`import OpenImageIO`), never through Blender's image save, so the bytes are explicit, with the colour space attribute `sRGB` on the albedo and `linear` on the other two (review: the first bake tagged every map sRGB): each map flipped to top row first, the albedo encoded to sRGB by the standard formula (`1.055 * x^(1/2.4) - 0.055` above 0.0031308, `12.92 * x` below) and the other two linear, all three as 8 bit RGB, to `data/materials/textures/<name>_albedo.png`, `<name>_normal.png`, `<name>_surface.png`.
- The seam check printed per map, from the arrays before encoding: `SEAM <map> left_right=<mean |column 0 - last column|> top_bottom=<mean |row 0 - last row|> column_step=<mean step between adjacent columns over the image> row_step=<the same over rows> <ok|check>`, four decimals, ok when each seam is at most 1.5 times its step (review: the bake's own sampling noise exceeds a single column pair's step).
- Short procedures: reading the parameters, the torus coordinate nodes, one procedure per channel, the bake, the normal, the encoding, the writing, the seam check, `main`.

Verify: the bake command above (absolute path), then `python3 -c "import struct; [print(name, struct.unpack('>II', open(f'data/materials/textures/painted_steel_{name}.png','rb').read()[16:24])) for name in ('albedo','normal','surface')]"` prints 512 512 three times, and the printed seam differences are no larger than the neighbour differences.
